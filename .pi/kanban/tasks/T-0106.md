Hermes: t_2f42ad2d (зеркало; борд записи — .pi/kanban)

Bug: In features/items/Items.kt:184 the chip row is gated by `if (ui.tagOptions.isNotEmpty())`. tagOptions comes from Deps.tags.observeAll() (lines 99-103). The dashboard (features/dashboard/Dashboard.kt:142-146, :486) navigates to `items/<tag>` for tags that may not exist in the dictionary. The filter is applied at Items.kt:120,125 regardless of the dictionary, so a tag outside the dictionary leaves the filter active but the chip row invisible — the user cannot see or remove the filter.

Fix:
1. Remove the `isNotEmpty()` guard so the chip row always renders.
2. Ensure the row always contains at minimum: an "All" (reset) chip and, if a tag filter is active in the ViewModel, a chip for that tag (even if it's not in tagOptions).
3. Existing tagOptions chips continue to render alongside.

TDD:
- Write a Compose UI test (or ViewModel test) that sets a tag filter to a value NOT in tagOptions, asserts the chip row is visible, asserts the "All" chip is present, and asserts tapping "All" clears the filter.
- Run the test, watch it fail, implement the fix, watch it pass.
