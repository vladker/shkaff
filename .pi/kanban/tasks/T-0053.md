Статус в TODO: NEW (глубокий анализ 07.11.2026).

- Доказательство: все репозитории штампуют `System.currentTimeMillis()` (напр. `data/repository/ItemRepository.kt:87,118,142,163`, `StorageRepository.kt:71,93` и т.д.), `MergeEngine` выбирает победителя строго по этим меткам (`sync/MergeEngine.kt:124`) — при рассинхроне часов устройств (типично для офлайна без NTP) побеждает устройство с «более быстрыми часами», а не более поздняя правка.
- Практика извне: wall-clock LWW при skew теряет причинно-более новые данные (tiarebalbi.com «Hybrid Logical Clocks: Fix Last-Write-Wins», back4app glossary offline-first sync, StackExchange-обсуждения). Полный HLC приложению не нужен.
- Вариант (вписать в ограничения: без облака, org.json, текущая схема): в репозиториях `val now = maxOf(System.currentTimeMillis(), (existing?.updated_at ?: 0L) + 1)`; дополнительно в `schema_meta` хранить максимальную наблюдаемую метку (обновлять при merge/PULL) и от неё тоже отталкиваться. Один общий хелпер `nextStamp(prev)`.

Критерий готовности: правка в app/ или llama/ + тест(ы) на чистую логику (TDD: сначала RED), `:app:testDebugUnitTest` и `:app:assembleDebug` зелёные, `adb install -r app/build/outputs/apk/debug/app-debug.apk` на SM-S928B. Git — с `--ignore-submodules=all`; коммит `<эмодзи> <тип>: <описание>`.
