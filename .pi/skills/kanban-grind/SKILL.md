# Прогон доски «Шкафа»

Одна карточка за раз, строго последовательно, в основном чекауте (worktree не создавать: картроки задевают общие файлы — `MainActivity.kt`, `Dashboard.kt`, `Dao`s). Борд — единственное состояние прогона: контекст может компактиться, доска нет.

## Вход

1. `kanban_list { status: "new", limit: 500 }` — очередь прогона. Плюс `kanban_list {}` целиком: если есть карточка в `doing`/`waiting_device`, захваченная мёртвым хэндлом, забрать её (`kanban_assign` c `force: true` и `reason: "grind: владелец мёртв"`) и доделать первой.
2. Гигиена дерева: `git status --short --ignore-submodules=all`. Если в дереве чужие незакоммиченные правки (не этого прогона) — остановиться и спросить: гринд начинает с чистого дерева. Незакоммиченные RED-тесты, описанные в карточке (`⚠ В рабочем дереве…`), — не «чужие»: это начало этой карточки.
3. Создать цель: `create_goal` с `mode: "sisyphus"`, `objective` — «Реализовать карточки T-XXXX…T-YYYY доски .pi/kanban: для каждой — тест(ы) на чистую логику, зелёные `:app:testDebugUnitTest` и `:app:assembleDebug`, отдельный коммит, статус `done`. Телефон не трогать. Прогон завершается, когда карточек, годных к headless-проверке, не осталось». `token_budget` — только если пользователь его назвал.
4. Объявить режим: `adb install` в этом прогоне не выполняется (решение пользователя); APK только собирается.

## Порядок

Сортировка очереди: `[S]` → `[M]` → `[L]`, внутри — по id борда. Карточки, которые нельзя проверить без железа (принтер/Bluetooth/BLE/USB, физический сканер HID, камера и её preview, специфика экрана телефона/OneUI, загрузка GGUF с сети, печатный вывод), ставить в конец очереди; если они и там нелезут — пропустить по правилу «застрявшие» с комментарием `пропущено: нужен физический тест на устройстве`.

## Одна карточка

1. `kanban_move { to: "doing", agent: "grind-1" }` — это захват.
2. Прочитать карточку целиком (`kanban_list { task: ... }`) и названные в ней файлы. Правка — по конвенциям `AGENTS.md` (чистая функция + тест, `MaterialTheme`, `updated_at` при изменении, мягкое удаление, русский UI).
3. TDD: сначала RED-тест на чистую функцию/VM, затем реализация — GREEN.
4. Проверка: точечный тест → полный `.\gradlew.bat :app:testDebugUnitTest` → `.\gradlew.bat :app:assembleDebug`. Чужие падения (WIP соседей, задокументированный флейк) не считать своими — сверить список падений до и после правки.
5. `git add <пути>` и коммит `<эмодзи> <тип>: <описание>` (одна карточка — один коммит). Git-команды с `--ignore-submodules=all`, где эта опция допускается (status/log/diff); `git add` — без неё.
6. Бухгалтерия источника (см. ниже), затем `kanban_move { to: "done", agent: "grind-1" }` и `kanban_comment` с хешем коммита и фразой `adb install не выполнялся (режим прогона без телефона)`.
7. Сразу следующая карточка — без отчёта «готово, продолжаем?» и без ожидания ответа. Промежуточный отчёт (1–2 строки) не является окончанием работы.

## Застрявшие карточки

Попытка = один полный цикл п.3–4. Не вышло (тесты не сходятся, нужен девайс, требование неоднозначно) → `kanban_comment` с причиной и вторичный заход. После второй неудачи: комментарий `⚑ 2 попытки: <что именно не так>` и `kanban_move { to: "new" }`; карточка в этом прогоне больше не берётся. Три карточки подряд, ушедшие в пропуск, — стоп и человеческий отчёт (цикл не должен крутиться впустую).

## Бухгалтерия вне борда

- `TODO_AGENT.md`: у закрытой записи заменить `- Статус: NEW` на `- Статус: ⚑ реализовано (<хеш>) — <1 строка что сделано>`.
- `PLAN_ONBOARDING.md`: пункт П0–П4 пометить `- [x] <дата> (<хеш>) …`, частичное — `[~]` с остатком.
- Эти два файла вне git; правки не коммитить. Карточку `T-0058` («установить APK на SM-S928B») в этом прогоне не закрывать.

## Остановка

Прогон завершается, когда в очереди не осталось карточек, годных к headless-проверке, или сработало правило трёх пропусков подряд. Тогда: краткий отчёт (сделано N из M, хеши; пропущено K с причинами; что требует телефона), обновить цель (`get_goal` → закрытие задач), карточки в `doing` не оставлять.

## Возобновление

Начинать с п.1–2 «Вход»: прерванный прогон определяется по захваченным `doing`/`waiting_device` и незакрытым `⚑ 2 попытки`. Цели прошлых прогонов не возобновлять — создать новую.

## Запреты

Не редактировать `status`/`assignee`/`history`/`rev` руками. Не трогать `app/`/`llama/` вне текущей карточки, не рефакторить «попутно». Не запускать `adb`, принтер, эмулятор. Не добавлять карточки в борд во время прогона — находки писать в `TODO_AGENT.md` (раздел ИДЕИ/ДЕФЕКТЫ), а не в доску.

## Project overrides

- verification command: `.\gradlew.bat :app:testDebugUnitTest`
- build gate: `.\gradlew.bat :app:assembleDebug`
- device install: выключено по решению пользователя (APK не ставить, карточка `T-0058` открыта)
