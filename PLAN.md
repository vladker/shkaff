# «Шкаф» — приложение для инвентаризации вещей и их хранения

**Статус:** утверждён (05.09.2026); расширен пользовательскими историями US-A…US-H и M8–M13 (06.09.2026)
**Платформа:** Android, minSdk 26 (Android 8.0), targetSdk 34
**Package:** `ru.vldkr.shkaff`

---

## 1. Задача

Упорядоченное хранение множества мелких вещей:
- учёт вещей: фото, номер/код, атрибуты, локация хранения;
- учёт систем хранения (шкафы, стеллажи) с фото и кликабельной разметкой ящиков/коробок;
- генерация штрихкодов/QR в виде картинок по шаблонам; поддержка номеров, написанных от руки;
- сканирование: камера смартфона (приоритет) + внешний USB/BT сканер;
- удаление фона на фото предмета (локально + опционально облако);
- экспорт базы в один файл (локально / сетевая папка / онлайн-хранилище);
- слияние двух баз с обработкой конфликтов;
- печать этикеток на 58-мм принтере (ESC/POS) — через приложение принтера (основной путь) или напрямую по Bluetooth / сети.

База данных проектируется с расчётом на рост функционала.

Расширенная дорожная карта — пользовательские истории (§2, US-A…US-H) и майлстоны M8–M13 (§10).

## 2. Пользовательские истории (US)

Приоритеты: **M** — Must, **S** — Should, **C** — Could. Порядок реализации — §10 (M8–M13).

### A. Быстрый ввод и массовые операции

**US-A1 · Массовый ввод однотипных объектов** — M
- На первом объекте серии галочкой «вводить для каждого» отмечаю изменяемые атрибуты; не отмеченные копируются из первого.
- Общие поля (название-паттерн, локация, категория, фото) префиллятся для всех следующих.
- Автонумерация (US-A2) продолжается по серии; в конце — список созданных и пачечная выдача этикеток.

**US-A2 · Автономера объектов любого уровня + немедленный QR** — M
- При создании storage / location / item присваивается уникальный номер: настраиваемый префикс + последовательность, раздельно по типу сущности (storage — `code`, location — `label`, item — `code`).
- Ручной номер остаётся возможен (override); дубликат блокируется (уникальный индекс на `item.code`).
- Кнопка «Выдать QR/этикетку» сразу после создания — рендер по шаблону, в галерею / печать.

**US-A3 · Справочники (категории и т.п.) — дополняемые inline** — M
- Справочники (select-атрибуты) редактируются прямо в форме объекта: «+ добавить значение» сразу пишет в словарь и подставляет.
- Справочник необязателен: объект сохраняется без значения.

**US-A4 · Черновик с автосохранением** — S
- Форма создания/редактирования автосохраняется черновиком (`draft`) на каждое действие.
- Черновик восстанавливается при повторном открытии; сбрасывается после успешного сохранения.

### B. Умный ввод вещи (EAN, LLM, фото)

**US-B1 · Скан рыночного штрихкода → заполнение из интернета** — S
- Считываю оригинальный EAN вещи; приложение запрашивает данные (OpenFoodFacts / UPCitemdb / GS1, при неудаче — LLM).
- Найденные поля сопоставляются с существующими атрибутами; недостающие предлагаются к добавлению в карточку **и** в словарь.
- В карточку попадают только подтверждённые пользователем поля.

**US-B2 · Поле «оригинальный штрихкод» (фото + числа)** — M
- В карточке вещи — поле `ean` (расшифровка числами) и/или фото штрихкода.
- Заполняется сканом (камера/внешний) или вручную; виден в карточке и в экспорте.

**US-B3 · LLM-агент (облако или локально, напр. Qwen)** — S
- Агент отвечает на вопросы («куда положить…», «что проверить…»), помогает упорядочить хранение и дозаполнить карточки, выступая инструкцией.
- Работает на контексте БД (категории, хранилища, объёмы, история).
- Режимы: облачный API (Qwen / OpenAI-compatible) по умолчанию, локальный (Ollama / на устройстве) — офлайн-фолбэк; переключатель в настройках.

**US-B4 · Поиск по фото через браузер** — C
- Кнопка «Найти в интернете» отправляет фото вещи в поиск по картинке (через браузер, напр. Yandex).
- Возврат в приложение; найденные атрибуты можно перенести в карточку.

### C. Иерархия, объём, масса, рекомендации

**US-C1 · Гибкая иерархия хранилищ** — S
- Базовая цепочка: город → склад → комната → шкаф → полка → коробка → пакет → объект.
- Уровни расширяемы вертикально и горизонтально (`level` на storage/location), но вложенность всегда однозначна и видна в UI — ни пользователь, ни приложение не путаются.

**US-C2 · Визуализация хранилищ** — S
- Три режима: фото, загружаемое изображение, отрисовка стандартными блоками прямо в приложении.
- Кликабельные области (редактор разметки) работают поверх любого режима.

**US-C3 · Объём хранилищ** — S
- У хранилища задаётся ёмкость: коробка — внутренние Д×Ш×В, пакет/мешок — литры.
- Показ занятого (`currentVolume`) и остатка места после добавления объекта; предупреждение при превышении.

**US-C4 · Масса и грузоподъёмность** — S
- Хранилище накапливает массу вещей; опциональная грузоподъёмность (напр. пакет 25 кг) — нельзя нагрузить больше.
- Галочка «не заполнять до упора» — резерв места (удобно для поиска, чтобы не вываливалось).
- Пользователь может принудительно пометить хранилище «полное» — добавление блокируется (вручную или по лимиту).

**US-C5 · Температура и влажность** — C
- У хранилища атрибуты температуры и влажности; пока — ручной ввод.
- Позже — получение значений от датчиков по протоколу (MQTT/BLE, M13).

**US-C6 · Рекомендуемое хранилище при добавлении** — C
- По атрибутам, массогабаритам и заполненности программа предлагает хранилище с плюсами/минусами: объекты той же категории/аналоги, свободное место, близость к пользователю.
- Пользователь в начале работы указывает свою локацию — она участвует в ранжировании.

### D. Жизненный цикл вещи и напоминания

**US-D1 · Срок годности** — M
- У вещи — дата окончания срока годности (хранятся и продукты).
- Напоминание/подсветка скоро истекающих на дашборде и в карточке.

**US-D2 · Плановый осмотр / обслуживание** — S
- У вещи — дата планового осмотра (протереть, смазать, проверить герметичность) + заметка.
- Напоминание о наступлении срока.

**US-D3 · Временная выдача + напоминание о возврате** — S
- Вещь или хранилище можно пометить «выдано временно» (кому, когда, до когда).
- Приложение помнит активные выдачи и напоминает, что пора вернуть; действие «возврат» закрывает выдачу.

### E. Извлечение и группировка

**US-E1 · Корзина извлечения + алгоритм** — C
- Формирую список вещей для извлечения («корзина»).
- Приложение группирует действия по уровням: несколько предметов в одной коробке/локации — один шаг.
- Настройки сортировки: сначала хранилища с большим числом вещей из корзины; сначала мелкие предметы; по глубине вложенности; по близости к локации пользователя (набор расширяем).

**US-E2 · Стеки** — C
- Объединяю вещи и/или хранилища в стек — стек получает собственный дополнительный номер.
- Входящие объекты не теряют информацию и оригинальные номера: стек — дополнительный взгляд (группа), а не перенос.

### F. Служебные QR и журнал

**US-F1 · Служебные QR-коды действий** — S
- QR кодирует действие: добавить хранилище / объект; переложить объект / хранилище; удалить объект / хранилище; временно передать объект / хранилище; экспортировать БД; импортировать БД; импортировать инкремент; распечатать последние N действий; показать/распечатать журнал пользователей; «скопировать отсканированный объект и выдать новый QR».
- Скан служебного QR на любом устройстве выполняет действие (с учётом прав профиля).

**US-F2 · Журнал действий** — S
- Приложение пишет журнал: кто (профиль), что (действие), над чем (объект/хранилище), когда, с какого устройства.
- Просмотр последних N, фильтр по типу/периоду, печать и экспорт.

### G. Пользователи, права, федерация БД

**US-G1 · Профили с разными правами** — S
- Выбор активного профиля при работе; права ограничивают действия.
- Пресеты: полный доступ (админ), только добавление в хранилища, только перекладка внутри хранилищ, только просмотр; состав расширяем.

**US-G2 · Админ-права и пир-синхронизация баз** — C
- Админ-права существуют в БД; можно подключить БД другого админа по LAN и синхронизироваться.
- Подключение необязательное и асимметричное: новая БД может быть присоединена без передачи прав на свою БД (флаги доверия в `peer_db`).

**US-G3 · Разделение / слияние БД по параметрам** — C
- Безопасный выгруз-фрагмент: только конкретные локации (или несколько), только объекты/хранилища за день/неделю/месяц.
- Фрагмент — валидная база; с общей базой (или другим фрагментом) снова склеивается без потерь.

### H. Экспорт

**US-H1 · Экспорт в xlsx и csv** — S
- Вся база хранения выгружается таблицами: вещи, хранилища, ящики; атрибуты — колонками.
- Форматы xlsx и csv; сохранение через SAF/Share.

## 3. Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Стек | Kotlin + Jetpack Compose (нативный Android) |
| БД | Room (SQLite) + FTS5-полнотекстовый поиск |
| Слияние баз | LWW + водяной знак; конфликты — выбор «всё из A/B» или поле за полем |
| Удаление фона | TFLite u2net на устройстве (по умолчанию, офлайн) + облачный API по ключу (опция) |
| Пользователи | именованные профили + роли (админ / добавление / перекладка / просмотр), локально, без паролей (offline-first) |
| LLM | облачный API (Qwen / OpenAI-compatible) по умолчанию + локальный Ollama / на-устройстве — офлайн-фолбэк; переключатель в настройках |
| Данные по штрихкоду | OpenFoodFacts / UPCitemdb / GS1; LLM-фолбэк; только подтверждённые пользователем поля попадают в карточку |
| Федерация баз | пир-синхронизация по LAN с флагами доверия (асимметричные права) |
| Датчики temp/humidity | пока ручной ввод; MQTT/BLE — позже (M13) |
| Экспорт таблиц | xlsx (FastExcel) + CSV в дополнение к ZIP-бэкапу |
| Печать | 58-мм ESC/POS; BT SPP и сеть `IP:9100` как прямые пути; PNG + Share в приложение принтера — гарантированный путь; размеры задаются на шаблон |
| Экспорт | один ZIP: `manifest.json` + фото; сохранение через SAF (локально/SMB/OneDrive/Drive) и Share |

## 5. Модель данных

Принципы: UUID-идентификаторы; мягкое удаление (`deletedAt`); `createdAt/updatedAt`; `deviceLastModified` (какое устройство меняло); гибкие атрибуты (JSON + словарь).

```
storage          id, name, description, attributes JSON,
                 code (автонамер, напр. "S-07"; ручной override),
                 photoPath, parentId?,
                 level (city|warehouse|room|wardrobe|shelf|box|bag|… — расширяемо),
                 capacityVolume (л/м³: коробка — Д×Ш×В, пакет — литры), capacityWeight (кг, опц.),
                 currentVolume, currentWeight (накоплено от содержимого),
                 dontFillToBrim (bool — резерв места), isFull (bool — ручная блокировка),
                 temperature, humidity (°C, % — пока вручную, позже датчики),
                 stackId → stack? (nullable),
                 createdAt, updatedAt, deletedAt, deviceLastModified

location         id, storageId → storage, parentId → location  (вложенность: шкаф→полка→коробка),
                 label   (автонамер, напр. "B-14"; ручной override),
                 name, attributes JSON, photoPath,
                 level, capacityVolume, capacityWeight, currentVolume, currentWeight,
                 dontFillToBrim, isFull, temperature, humidity, stackId?,
                 createdAt, updatedAt, deletedAt, deviceLastModified

item             id, code (автонумерация prefix+seq; ручной override; уникальный индекс),
                 name, description, attributes JSON, photoPath,
                 ean (оригинальный рыночный штрихкод), expirationDate?, maintenanceDate?,
                 locationId → location? (nullable),
                 stackId → stack? (nullable),
                 createdAt, updatedAt, deletedAt, deviceLastModified

annotation       id, storageId → storage, locationId → location,
                 shape (rect|polygon), points JSON (нормализовано 0..1 — не зависит от разрешения фото),
                 label, color, zOrder

label_template   id, name,
                 format (QR|CODE128|EAN13|DataMatrix|PDF417),
                 widthMm, heightMm, marginMm,
                 showText, textContent (шаблон: {name} {code} {date}),
                 fontSize, textColor, bgColor, invert, logoPath, quietZone

attribute_def    id, scope (item|location|storage|*), key, label,
                 type (text|number|bool|date|select), options JSON,
                 sortOrder, required

printer_profile  id, name, transport (tcp|bt),
                 host, port (9100), btMac,
                 protocol (escpos), paperWidthMm (58), offsetXmm, offsetYmm,
                 testNote

conflict_log     id, entityType, entityId, field, valueA, valueB, chosen, resolvedAt

schema_meta      key, value   -- schemaVersion, lastSyncWatermark, deviceId,
                                 numberSeq_<scope> (счётчики автонумерации)

user             id, name, role (admin|add|move|view), permissions JSON,
                 createdAt, updatedAt, deletedAt, deviceLastModified

loan             id, entityType (item|storage), entityId → item/storage,
                 borrower, note, lentAt, dueAt?, returnedAt?

action_log       id, userId → user, action (add|move|delete|lend|return|export|import|…),
                 entityType, entityId, detail JSON, at, deviceId

stack            id, name, code (автонумер),
                 createdAt, updatedAt, deletedAt, deviceLastModified
stack_member     id, stackId → stack, entityType (item|storage), entityId, sortOrder
                 (члены сохраняют свою идентичность и оригинальные номера)

peer_db          id, peerDeviceId, trust JSON (области и права пира), lastSyncedAt,
                 createdAt, updatedAt, deletedAt

sensor           id, storageId → storage, protocol (manual|mqtt|ble), address,
                 lastTemp, lastHumidity, lastAt, updatedAt

draft            id, entityType, entityId?, formJson, savedAt
                 (черновик формы — автосохранение на каждое действие)
```

Почему так:
- **Атрибуты**: JSON на сущности + словарь `attribute_def` → новые атрибуты без миграции, UI рисует типизированные поля, фильтры по словарю.
- **Нормализованные координаты аннотаций** — подписи не смещаются при смене разрешения фото.
- **Вложенные locations** — иерархия хранения без новых сущностей.
- **FTS5** по `name/description/code` — быстрый поиск.
- **Room migrations** + `schema_meta.schemaVersion` — безопасный рост.
- **Автономера**: prefix+seq раздельно по типу сущности (счётчики в `schema_meta`); ручной override сохраняется.
- **Заполненность**: `capacity*` — заявленный лимит, `current*` — сумма от содержимого; `dontFillToBrim` резервирует долю, `isFull` — жёсткая блокировка добавления.
- **Стеки** — отдельный взгляд на вещи/хранилища в группах, без переноса и потери оригинальных номеров.
- **Профили / журнал / выдачи** — аудит и права без учётных записей: локальные именованные профили.

## 6. Экраны и сценарии

### Экраны
1. **Главная** — статистика (вещи/ящики/шкафы), поиск, глобальная кнопка скана.
2. **Хранилища** — список; добавление с атрибутами (по словарю).
3. **Хранилище** — фото с кликабельной разметкой ящиков; список ящиков; действия.
4. **Ящик (location)** — вещи внутри, фото ящика, атрибуты, этикетка.
5. **Вещь (item)** — фото (оригинал/вырезка), код, атрибуты, локация, этикетка, действия.
6. **Шаблон этикеток** — создание/редактирование, предпросмотр, генерация PNG.
7. **Принтеры** — профили, поиск по сети/BT, тестовая печать.
8. **Импорт/Экспорт** — сохранение/выбор файла, запуск слияния.
9. **Конфликты** — разрешение по записям и по полям.
10. **Настройки** — deviceId, облачный API ключ фона, сканер (prefix/suffix), тема.
11. **Массовый ввод** — серия однотипных объектов: галочки «вводить для каждого», автонумерация, пачечные этикетки.
12. **Профили** — выбор активного профиля; роли и права (админ / добавление / перекладка / просмотр).
13. **Выдача** — временная передача вещи/хранилища (кому, срок), активные выдачи, напоминания, возврат.
14. **Журнал** — последние N действий (кто/что/когда), фильтр, печать/экспорт.
15. **Служебные QR** — генерация QR-действий и их выполнение по скану.
16. **Корзина извлечения** — список вещей к извлечению, алгоритм по уровням, настройки сортировки.
17. **Стеки** — создание/редактирование стека (номер, состав), вид группы.
18. **Агент (LLM)** — диалог: подбор места, дозаполнение карточки, подсказки; режим «облако / локально».
19. **Табличный экспорт** — xlsx/csv (вещи/хранилища/ящики), атрибуты колонками.
20. **Федерация** — пир-базы: подключение по LAN, область и права, синхронизация.

### Ключевые сценарии
1. **Хранилище:** добавить → атрибуты → фото → **редактор разметки**: тап создаёт прямоугольник; перетаскивание/уголки; подпись «B-14»; цвет. Области кликабельны — тап открывает ящик.
2. **Вещь:** в ящик добавить вещь → фото → номер (ручной ввод / генератор: prefix+seq / рандом) → атрибуты.
3. **Этикетка:** шаблон → рендер QR/CODE128 (203 dpi) → PNG → галерея / печать / Share.
4. **Скан:** камера (CameraX + ML Kit) — приоритет; USB/BT HID-сканеры — перехват быстрого ввода в активное поле + настройка отбрасывания суффиксов (Enter и т.п.); ручной ввод — fallback. Скан с главной сразу открывает вещь/ящик.
5. **Удаление фона:** кнопка на фото вещи → локальная TFLite-модель (качается один раз, ~40–80 МБ, прогресс) → PNG с альфой; опционально облачный API по ключу. Оригинал и вырезка хранятся рядом, переключаются.
6. **Экспорт:** один ZIP → локальная папка / SAF (SMB, OneDrive, Dropbox, Drive) / Share.
7. **Слияние:** импорт ZIP → движок → при конфликтах — экран разрешения.
8. **Массовый ввод:** «N однотипных» → первый объект + галочки «вводить для каждого» → серия с автонумерацией → пачка этикеток.
9. **Выдача:** вещь/хранилище → «Выдать» (кому, срок) → напоминание о возврате → «Возврат».
10. **Служебный QR:** сгенерировать QR-действие (напр. «переложить в B-14») → напечатать → отсканировать → действие с учётом прав профиля.
11. **Извлечение:** отметить вещи в «корзину» → «Сформировать алгоритм» → шаги, сгруппированные по хранилищам → выполнение по чек-листу.
12. **Агент:** «Куда положить дрель?» → топ-кандидаты с плюсами/минусами; «Заполни карточку» → предложенные поля из интернета/LLM.
13. **Пир-синхронизация:** добавить пир по LAN → область и права → синхронизация → запись в журнал.

## 7. Печать (58 мм, ESC/POS)

Два слоя (адаптерный дизайн):

1. **Гарантированный путь:** этикетка → PNG (203/300 dpi) → галерея + системная Share → приложение принтера.
2. **Прямое подключение (экран «Принтеры»):**
   - **Сеть:** mDNS-обнаружение + ручной ввод `IP:9100`; raw TCP-сокет.
   - **Bluetooth:** классический SPP (RFCOMM, канал 1); список устройств, запрос сопряжения, фильтр по имени.
   - **Профиль принтера в БД** (`printer_profile`): транспорт, адрес, ширина 58 мм, смещения; тестовая печать.
   - **Протокол:** ESC/POS, raster-вставка `GS v 0` (bit image), команды `GS h` (двойной размер), обрезка по ширине.

Рендер строго **203 dpi (8 dot/mm)**: 58 мм = 464 px, 40 мм = 320 px. Размеры задаются на шаблон.

Разрешения: `BLUETOOTH_CONNECT`, `BLUETOOTH_SCAN` (Android 12+), `BLUETOOTH/BLUETOOTH_ADMIN` (<12), `INTERNET`, `ACCESS_NETWORK_STATE`; для BT discovery до Android 11 — геолокация.

Структура: `domain/printer/` → `LabelRenderer` (мм→px), `PrintJob`, `Transport` (interface: `ShareTransport`, `TcpTransport`, `BtSppTransport`), `EscPosProtocol`.

## 8. Экспорт / слияние баз

### Формат экспорта (один файл)
ZIP:
```
manifest.json          { schemaVersion, deviceId, lastSyncWatermark,
                         storage[], location[], item[], annotation[],
                         label_template[], attribute_def[], printer_profile[] }
photos/                <entityId>_<kind>.<ext>
```
JSON (не сырой SQLite) — независимость от версий БД при росте.

### Сохранение
- локальная папка (SAF);
- сетевая папка (SMB) и онлайн-хранилища (OneDrive/Dropbox/Drive) — как SAF-каталоги;
- системный Share.

### Алгоритм слияния (2-way, offline-first)
1. Базы A (локальная) и B (импорт). `lastSyncWatermark` из последнего успешного мержа определяет «изменилось с обеих сторон».
2. По каждой сущности (по UUID):
   - только в A → оставить;
   - только в B → вставить;
   - обе живые:
     - содержимое идентично → ничего;
     - изменилась только одна (по `updatedAt` vs watermark) → берём её (LWW);
     - изменились **обе** → очередь конфликтов.
   - tombstone (удалена с одной стороны) vs изменение с другой → конфликт «удалено/изменено».
3. **Конфликт-экран:** две карточки бок о бок; «всё из A/B» или **поле за полем** (имя, локация, атрибуты, фото — для фото показываем оба, выбираем одно). Решения пишутся в `conflict_log`.
4. **FK-консистентность:** вещь без ящика → «без локации» (с уведомлением); ящик без шкафа → наверх (с подтверждением).
5. После мержа `lastSyncWatermark = now`.

Движок — чистый Kotlin, полный набор юнит-тестов: LWW, обе изменены, tombstone vs изменение, переезд вещи, вложенность, идентичные записи.

## 10. Майлстоны

Каждый завершается рабочым приложением.

1. **M1** — Каркас: Gradle, Compose, Room, навигация; CRUD storage/location/item; атрибуты; поиск.
2. **M2** — Этикетки: шаблоны, рендер 203 dpi, PNG, предпросмотр, сохранение в галерею.
3. **M3** — Сканер: камера + HID + ручной ввод; настройки prefix/suffix.
4. **M4** — Фото + редактор разметки хранилища (кликабельные области, перетаскивание).
5. **M5** — Удаление фона: TFLite u2net + облачная опция; переключение оригинал/вырезка.
6. **M6** — Экспорт/импорт ZIP + merge-движок (с тестами) + конфликт-экраны.
7. **M7** — Печать: ESC/POS, BT SPP, TCP 9100, профили принтеров, тестовая печать; полировка, тёмная тема, релиз.
8. **M8** — Быстрый ввод и экспорт: массовый ввод однотипных (US-A1), автонумерация всех сущностей + немедленный QR (US-A2), inline-справочники (US-A3), автосохранение черновиков (US-A4), срок годности (US-D1), экспорт xlsx/csv (US-H1); уникальный индекс на `item.code` + миграция.
9. **M9** — Заполненность и подбор: объём хранилищ (US-C3), масса/грузоподъёмность/«не до упора»/«полное» (US-C4), рекомендуемое хранилище с плюсами-минусами + локация пользователя (US-C6).
10. **M10** — Люди и аудит: профили/роли (US-G1), временная выдача + напоминания (US-D3), служебные QR (US-F1), журнал действий (US-F2).
11. **M11** — Умный ввод: поле EAN + фото (US-B2), заполнение по штрихкоду из интернета (US-B1), LLM-агент облако/локаль (US-B3), поиск по фото через браузер (US-B4).
12. **M12** — Структура и группировка: уровни иерархии (US-C1), визуализация фото/изображение/блоки (US-C2), стеки (US-E2), корзина извлечения с алгоритмом (US-E1).
13. **M13** — Федерация и датчики: пир-синхронизация по LAN с флагами доверия (US-G2), разделение/слияние БД по параметрам (US-G3), датчики temp/humidity (US-C5).

При необходимости M7 (печать) можно перенести раньше M6.

## 11. Риски и меры

| Риск | Мера |
|---|---|
| HID-сканеры передают разные суффиксы | Настройки prefix/suffix; тест на реальном сканере (M3) |
| mDNS у 58-мм принтеров часто отсутствует | Ручной ввод `IP:9100` обязателен (M7) |
| u2net на слабых телефонах 1–3 с/фото | Прогресс-индикатор, кэш результата, фоновый поток |
| Merge — самый сложный блок | Движок и тесты пишутся первыми внутри M6 |
| Размер фото раздувает ZIP | Сжатие при сохранении (≤1600 px, JPEG 85) |
| Рост функционала ломает БД | Room-миграции + schemaVersion в manifest экспорта |
| LLM на слабых устройствах / офлайн | облако по умолчанию + локальный фолбэк (Ollama / LiteRT-LLM), кэш ответов, фоновый поток |
| Точность EAN-данных из интернета | только подтверждённые пользователем поля попадают в карточку/словарь |
| Пир-синхронизация: права и конфликты | флаги доверия в `peer_db`, область синхронизации по узлам, LWW + conflict_log |
| Черновики и журнал раздувают БД | периодическая очистка `draft`/`action_log`, индексы по entityId |
